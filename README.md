# soft-quality-eval · 软质量评测（说人话）

**评测一份回答「说没说人话」**——不是文笔，是读者能不能一次读懂、能不能高效拼出答案。

十一项，分两半：

- **措辞层**（3 项）：每个词、每个句子本身好不好懂
- **信息组织层**（8 项）：散在文中的信息，读者能不能高效拼起来

```
git clone git@github.com:stardust-yao/soft-quality-eval.git
cd soft-quality-eval
pip install -r requirements.txt
python tests/test_reproduce.py                    # 先验环境（11 项锚点）
python -m plaineval.cli cases/demo --html out/report.html
```

## 一、十一项

### 措辞层

| # | 对象 | 读者心里问的 | 归属 |
|---|---|---|---|
| **A1** | 词汇多样性 | 用词是不是翻来覆去就那几个 | 基线（权重 0） |
| **A2** | 用词熟悉度与解释 | 这个词我不认识，他说了吗 | **评估（唯一计分项）** |
| **A3** | 句法（句长 / T-unit） | 一句话里塞了几件事 | 基线（权重 0） |

### 信息组织层

| # | 对象 | 读者心里问的 | 归属 |
|---|---|---|---|
| **B1** | 有没有（覆盖） | 我问的几件事都答了吗 | 评估 |
| **B2** | 在哪（定位） | 我要的东西在第几段 | 基线 |
| **B3** | 散不散（集中） | 同一件事要不要翻几处 | 基线 |
| **B4** | 层级（结构形态） | 块怎么切、层级多深 | 基线 |
| **B5** | 状态 vs 推理 | 那到底什么状态 | 评估 |
| **B6** | 有没有废话 | 删了我会少知道什么 | **观察（不计分）** |
| **B7** | 指代清不清 | 「这一项」是哪一项 | 评估 |
| **B8** | 数量自述对不对 | 到底几件事要我拍板 | 评估（零争议） |

## 二、为什么分「基线 / 评估 / 观察」

判断归哪边，**看的不是"能不能自动算"，而是"这个数本身有没有好坏"**。

| | 基线 | 评估 | 观察 |
|---|---|---|---|
| 判据 | 看不出优劣，等数据够了划阈值 | 能明确判定为错 | 判定有结构性争议 |
| 例子 | 句长 28 字 vs 24 字，谁更好？没定论 | 说「三组」实际四组 | 引导句算不算废话 |
| 现在怎么用 | 只报数 | 直接扣分 | 只列清单 |

**进扣分项还有一道硬门槛**：换一个评委看同一处，必须给出相同判定。达不到就不算"明确错误"。

## 三、case 目录

```
cases/你的case名/
├── case.md              # 题目
├── a.md                 # 回答 A
├── b.md                 # 回答 B
├── aspects.json         # 诉求清单 + 落点 + QUD + 概念清单路径
├── judgments_a.json     # A2 逐词判定（可选）
├── judgments_b.json
├── evidence_sources.json  # A2 的信息源清单（E1–E5）
└── scoring.json         # 计分输入（层3/层4）
```

`a.md` / `b.md` 直接粘贴原始输出，**不用清洗**。Markdown、纯文本、带链接都行。

`aspects.json` 是唯一需要动脑的地方：

```json
{
  "meta": {"case_id": "…", "a_name": "…", "b_name": "…", "human_preference": "B"},
  "qud":   [{"id": "Q1", "question": "两个方案各自怎样、有什么影响？"}],
  "aspects_a": [
    {"id": "aspect_1", "label": "比较两个方案", "blocks": [1],
     "keywords": ["方案A", "方案B"], "verdict": "有"}
  ],
  "aspects_b": [ ... ],
  "inventory": "cases/…/inventory.json",
  "judgments_a": "cases/…/judgments_a.json"
}
```

- `blocks`：这个诉求落在第几个语块（**0 = 第一个标题之前的开头段**）
- `verdict`：`有` / `部分` / `无` —— **人判后手填**
- `keywords`：只用于交叉校验，**不参与判定**
- `inventory`：A2 的概念清单，**领域相关，必须自己建**

详见 `docs/04-writing-cases.md`。

## 四、输出是什么

控制台对照表 + `out/result.json` + 单文件 HTML（可 Ctrl+P 导出 PDF）。

```
指标                                 A           B
------------------------------------------------
A1 词次 / 词型                 473 / 229   480 / 203
A1 MSTTR-50                   0.8311      0.7956
A2 未解释陌生概念数                      1           0
A3 句长均值                        28.19       20.38
A3 每 T-unit 从句数                 1.89        2.00
B1 缺口数                             1           0
B2 拍板位置%                        88.5        80.3
B3 延续率                        0.5385      0.5833
B4 列表项平均字数                      15.7        10.4
B7 需配对数                            1           0
B8 声明不一致数                          1           0
```

**基线的数不等于质量。** 句长、块数、集中度都没有绝对好坏——现在只报数，阈值等样本积累到几十组后再划。

## 五、三条最要紧的口径

### ① 语块按标题切，但要认「独立短行标题」和「压平表格」

- 有的回答全文没有 `#`，标题是独立短行（`建议结论`、`推荐执行顺序`）
- 有的回答全文**没有一个空行**，靠空行分段会算成 1 段
- 有的回答里的表格被压平成文本，**每个单元格都是短行**——当成标题会凭空多出 7 个块

### ② 作者句不切分号，并排除标题和表格格

实测一份结构化回答的 45 个"句子"里，**8 个是独立短行标题（18%）**，其中一份的句长被拉低 13%、延续率被压低 35%。

| | 未清洗 | 清洗后 |
|---|---|---|
| 句数 | 27 / 45 | **27 / 37** |
| 句长均值 | 28.19 / 17.96 | 28.19 / **20.38** |
| 延续率 | 0.5385 / 0.4318 | 0.5385 / **0.5833** |

### ③ 位置% 分母用清洗后正文

去掉 markdown 装饰符和链接 URL。实测一份回答 26.8% 的字符是 `[原消息](<https://…>)` 和加粗标记，直接算会把位置% 偏 4.5 个点。

**细节见 `docs/01-units.md`——改任何指标之前先读那一页。**

## 六、哪些要人工判

脚本只给**候选**，不给结论：

| 对象 | 人还要做什么 |
|---|---|
| **A2** | 逐词按 E1–E4 内部数据对照（**不需要读者确认**，但每条判定要带证据引用） |
| **B1** | 填 aspects：诉求清单 + 落点 + verdict |
| **B5** | 逐句判三档（① 完整状态 / ② 半状态+推理 / ③ 纯元话语） |
| **B6** | 逐句做删句测试（观察用） |
| **B7** | 逐处判：能否唯一确定 / 需不需要读者自己配对 |

**这不是偷懒。** 把语义判断做成脚本，等于把一个不可复核的判断藏进代码里。

注意 **A2 不需要读者确认**——它靠内部数据对照（问题原文 / 成员对话 / 项目资料 / 正文解释），
每条判定带证据引用即可。只有需要**校准**时才另请读者口径。

判题手册见 `docs/05-judging.md`。

## 七、已知边界

| 项 | 状态 |
|---|---|
| **B6 不计分** | 四种口径给出三个方向。引导句在删句测试下必然判无效，但它帮助扫读——**这是构造性矛盾，不是判定误差** |
| **A2 的 K 值 pending** | 只报计数，不产分数。一个未解释黑话该扣多少分取决于读者群体，没有跨 case 数据定 K 就是拍脑袋 |
| **B5 三档是自研** | 框架来自 QUDeval，三档划分无直接文献出处；需第二评者 |
| **B1 的 aspects 要人抽** | 抽漏了会误判"没缺口" |
| **位置% 依赖语块识别** | 已修表格误判，新格式仍可能错。字符类指标（跨度）不受影响 |
| **实体抽取是位置启发式** | 句首第一个名词当主语、动词后第一个当宾语，非依存句法分析 |
| **共指不解** | 纯词面。「前一份 → PPT」这类看不见 |
| **单份样本** | 一套 case 只说明这一题，不能推广 |
