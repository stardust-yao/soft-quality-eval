## A1 词汇多样性 · 基线（权重 0）

**测什么**：用词是不是翻来覆去就那几个。

| 指标 | 算法 |
|---|---|
| N 词次 | jieba 分词后的总词数 |
| V 词型 | 去重后的词种数 |
| H（nats） | 词频熵 = −Σ p·ln p |
| **MSTTR-50** | 按顺序切不重叠的 50 词段，段内 V/50，再取均值 |
| 词段 TTR 方差 | 各段 TTR 的方差 |
| 尾部丢弃词数 | 不足 50 词的尾段（**必须披露**） |

**MSTTR 怎么理解**：把文章切成若干个 50 词的窗口，每个窗口里"不重复的词占多少"。0.88 = 每个窗口里 88% 的词不一样。**越大 = 同窗口内重复越少 = 词汇越丰富。**

**但"丰富"不等于"好懂"。** 在可读性语境里，词汇丰富通常是减分项——生僻词多意味着读者要查词的次数多。

### 为什么权重 0

| 证据 | 数字 |
|---|---|
| 词频熵 H 与篇幅的 Spearman 相关 | **ρ = 0.935 / 0.950** → H 本质是"篇幅的替身" |
| MSTTR-50 与人工偏好的一致率 | **4/7** |
| MSTTR-50 与词频熵的相关 | **ρ = −0.05** → 两者测的不是同一件事 |

**所以 H 不报（它只是篇幅），MSTTR 只作基线。**

### 口径披露

**尾部丢弃词数必须报。** Case1 里 A 丢 4 词、B 丢 **47** 词——不披露的话，两份文本的 MSTTR 不在同一个可比口径上。

## A2 用词熟悉度与解释 · 评估（唯一计分项）

**测什么**：回答里出现的陌生说法，读者不认识，作者有没有解释。

**这是全部 11 项里唯一有资格计分的对象**，但**计分参数（K 值 / 封顶 / 合格线）目前 pending**，所以现在只产**计数**。

### 两件事可自动

```
① 候选发现：按一份固定概念清单在回答里定位（最长不重叠匹配）
② 汇总：读入逐词判定，按「绝对数扣分」算未解释陌生概念数
```

### 判定靠内部数据对照，不靠读者确认

**五类信息源**（写清楚是为了让判的人知道去哪找证据、找到什么算证据）：

| 编号 | 信息源 | 能证明什么 | 边界 |
|---|---|---|---|
| **E1** | 问题原文 | 这个词在用户自己的提问里已出现 | 出现 ≠ 会用 |
| **E2** | 成员自然对话（IM 一周校准） | 用户在日常表达里用过 | 排除测试指令；同词不同义不放行 |
| **E3** | 项目资料（工具实际返回的材料文本） | 项目语境里已存在这个概念 | **只认返回正文，不认调用参数/下载完成通知** |
| **E4** | 本轮回答自身 | 正文里已解释 | 只有定义或例子算解释，重复出现不算 |
| **E5** | Agent 自己的输出 | — | ❌ **禁止作为证据**（循环论证） |

**判定顺序**：

```
E1 命中              → 豁免（问题已给概念）
E4 命中              → 豁免（正文已有解释）
E2 或 E3 命中         → 豁免（内部已用）
全不命中 + 领域术语    → 未解释陌生   ← 这一档才扣分
材料缺失 / 检索不到     → 待查，不扣分
```

### 四条硬标准

| # | 标准 | 对应哪条源 |
|---|---|---|
| 1 | **调用参数 / 下载完成通知 ≠ 读到内容** | E3 的边界 |
| 2 | **不能把 Agent 自己说过的话当作用户常用的证明** | E5 禁用 |
| 3 | **同词不同义不放行** | E2/E3 匹配时要核义项 |
| 4 | **测试指令不计入自然对话词频** | E2 的边界 |

**不需要读者确认这一步。** 判定完全由内部数据对照得出；读者口径只在需要校准时另做，不是流程的一部分。

### 计数口径：绝对数，按概念去重

```
未解释陌生概念数 = 判为「未解释」的概念数（同一概念出现多次只算一次）
```

**不除以句数或篇幅。** 代价是长文本天然更容易出现生僻词——**接受这个偏差，并在报告里写出来。**

### 分母内生问题：三个数一起报

「适用概念数」算不算豁免类，没有定论。所以不合成比率，改报三个绝对数：

```
判过概念数    这次判了多少个概念
豁免数        判为「问题已给 / 正文已解释 / 日常用语」等，不算陌生
未解释数      判为「未解释陌生」 ← 这个才是问题
```

Case1：A 判过 5 / 豁免 5 / 未解释 **0**；B 判过 16 / 豁免 14 / 未解释 **2**（冒烟验证、低依赖Case）。

### 概念清单是领域相关的

仓库带的 `plaineval/data/inventory_example.json` 是**某个 回答 A 项目的 60 项例子**。

**换项目必须自己重建**：把该领域里「内行才懂、外行看到会卡住」的说法列出来。第二列是匹配正则，可以写同义写法（`风险和副作用分层|副作用分层`）。

### 已知边角

- 未命中 ≠ 读者不认识（词表没覆盖到）
- 「读到了」≠「理解了」（日志里有返回，不代表模型真读了）
- 没有自身读取轨迹的一方（如对照产品），证据全来自另一方的日志

## A3 句法 · 基线（权重 0）

**测什么**：一句话里塞了几件事。

| 指标 | 算法 |
|---|---|
| 句长均值 / P90 / 最长 | 汉字个数 |
| T-unit 数 | 一个主句 + 它带的从句 = 1 个 T-unit |
| **每 T-unit 从句数** | 从属复杂度 |
| **每句 T-unit 数** | 并列密度 |
| 超长句清单 | ≥60 字 |

### 为什么"只测不判"

**句长是提示，不是判据。** 长句不等于难读，短句也不等于清楚。所以做基线。

### 中文没有现成的 T-unit 库

LTP / HanLP / stanza 只给依存树，不直接出 T-unit。本实现用**连词规则近似**：

```
并列连词（并且/而且/同时/但是/以及/因此/所以/然后...）→ 切开，产生新 T-unit
从属连词（因为/如果/虽然/只要...）→ 不切，从句属于主句
```

**这是近似，报告里必须标注。** 表里还含「因此/所以/于是」这类连接副词，它们严格说属从属/承接关系，按并列处理是对齐既有口径的取舍。

### 三者的关系：只能留两个

```
句长 ≈ T-unit 均长 × 每句 T-unit 数
```

实测验证过：A 的 24.64 × 1.13 ≈ 27.8（实际 27.79），B 的 21.67 × 1.09 ≈ 23.6（实际 23.55）。

**所以「句长」「T-unit 均长」「每句 T-unit 数」三者只留两个，否则重复计分。**

### 句口径

**必须用清洗后的作者句**（见 `01-units.md`）：按 `。！？` 切、不切分号、排除标题和表格单元格。

不这么做的话，一份结构化回答的 75 个"句子"里有 28 个是标题和表格格，句长均值从 23.55 被拉到 18.65。
