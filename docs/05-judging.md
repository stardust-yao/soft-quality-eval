# 判题机制

> 自动指标能给出**候选**和**计数**，但九项里有五项需要人或 LLM 判档。
> **判题的质量决定这套评测能不能用。** 这一页讲怎么判、怎么验证判得对不对。

## 二、四种判题的问法（照这个问，别自己改）

### A2 用词熟悉度

**不是"问读者熟不熟悉"，是"拿内部数据对照"。** 判定顺序固定，不要跳步：

```
① E1  这个词在问题原文里出现过吗？        → 出现过 → 豁免
② E4  正文里有定义或例子吗？              → 有     → 豁免
③ E2  成员自然对话里用过吗？（排测试指令）  → 用过   → 豁免
④ E3  项目资料里出现过吗？（只认返回正文）  → 出现过 → 豁免
⑤ 全不命中 + 属于领域术语                 → 未解释陌生（扣分）
⑥ 材料缺失 / 检索不到                     → 待查，不扣分
```

**每条判定必须带证据引用**（哪条源、哪条记录、原句），否则不可复核。

### 四条硬标准

| # | 标准 | 违反的后果 |
|---|---|---|
| 1 | 调用参数 / 下载完成通知 ≠ 读到内容 | 把"调了检索"当成"读到了" |
| 2 | 不能把 Agent 自己说过的话当用户常用的证明 | 循环论证 |
| 3 | 同词不同义不放行 | 「基线」在统计语境常见 → 放过项目语境里的陌生用法 |
| 4 | 测试指令不计入自然对话词频 | 「用这个词造句」被算成用户会这个词 |

### 不需要读者确认

判定完全由 E1–E4 的对照得出。读者口径只在需要**校准**时另做一次（比如验证某批判定是否偏严），**不是流程步骤**。

### B1 覆盖

```
这个诉求是在哪个语块里被真正回答的？

· 「提到」不算，「回答了」才算
· 一个诉求可以落多个块，取第一个明确服务它的
· 找不到 → verdict = 无
```

**反例**：第一句出现了"方案A""方案B"，那是**提到**，不是**比较**。真正的比较在第 1 块。

### B5 状态 vs 推理

```
① 这句回答的是哪个预设问题（QUD）？
② 如果答的是「状态」，关键状态给了吗？

答不出来 → ③ 纯元话语
答了但关键状态缺 → ② 半状态 + 推理
答了且关键状态完整 → ① 完整状态
```

**实例对照**

| 原句 | 档 | 缺什么 | 改法 |
|---|---|---|---|
| 「不能用前一份的成功证明后一份已恢复」 | ② | 后一份到底恢复没有 | 「10月29日那份 PPT 恢复状态无法判定」 |
| 「同事甲曾报告两个模块上线失败，尚未核实到恢复成功」 | ① | — | （这句是对的：失败 + 恢复未知，两个状态都给了） |
| 「以上是建议，尚未据此改表」 | ③ | 不回答任何问题 | 删掉 |

**注意 ① 和 ② 的界限不在"有没有说不能推出"，而在"关键状态给了没有"。** 同一个作者可能一句给对、一句给错。

### B7 指代

```
① 这个回指词指向谁？
② 能列出几个合理对象？
     ≥2 个 → 指代不清
     只有 1 个 → 清楚
③ 同一句里出现了两个指代、要回前文数对象吗？
     要 → 「需配对」（可扣分）
```

**必做**：人工剔误报。「因此 / 据此 / 此前 / 此外 / 与此同时」里的「此」不是实体回指。

## 三、第二评者：怎么算"判得对"

### 最基本的一步：两个人各判一遍

```
① 报一致率 + 置信区间
   · 分类任务（熟悉/不熟悉/证据不足）→ Cohen's κ 或 Krippendorff's α
   · 连续评分 → ICC
② 报分歧清单（附每人的判定和理由）
③ 把分歧归类：
     · 定义模糊 → 补判定规则
     · 尺度不同 → 加锚点例子（每档 2 正例 2 反例）
```

**依据**：James (2026), LREC 2026, doi:10.63317/2wuxteb6uvcj —— IAA 应按任务类型选指标、报置信区间、分析分歧模式。

### 只报一致率是不够的——要报分歧模式

**反例（真实发生过）**：B6 废话的逐句一致率只有 24/45。如果只报"24%"，结论是"这个指标不能用"。

**拆开分歧模式**才发现：

```
分歧全部集中在「引导句」这一类
    「建议同时确认：」「需要确定：」
    → 排版上必要，但删句测试下必然判无效
```

**这是构造性矛盾，不是判定误差。** 换指标解决不了，只能换判据或不做。

### 一致率低的时候，先别改指标

```
错误做法：一致率低 → 换个指标 → 还是低 → 再换
正确做法：一致率低 → 看分歧集中在哪 → 补判定规则 → 重测
```

**指标换来换去，定义模糊的地方还是模糊。**

## 五、三个不要

| 不要 | 为什么 |
|---|---|
| **不要把语义判定做成脚本** | 等于把一个不可复核的判断藏进代码里 |
| **不要用关键词命中当"覆盖"的证明** | 词出现 ≠ 诉求被回答 |
| **不要在没有第二评者的情况下声称某项"有效"** | 单评者的结果只是"一个人这么看" |

## 六、判题的一致性怎么自查

跑完一批 case 之后，抽 10 句自己重判一遍：

```
同一句两次判定不一致 → 说明你的判据在你脑子里也不稳定
                    → 需要把那条规则写下来
```

**这是最便宜的一致率检验**，不需要第二个人。

## 七、A2 的 K 值为什么还没定

计分公式是：

```
A2 分 = 100 − K × 未解释陌生概念数     （封顶 / 合格线同样未定）
```

**K = 10 只是占位值，不是结论。** 理由：

- 一个未解释黑话到底该扣多少分，取决于读者群体（内部团队 vs 外部客户）
- 没有跨 case 的数据，定 K 就是拍脑袋

**所以现在只报计数。** 等积累到足够多 case、能量出"未解释数 vs 人工偏好"的关系，再定 K。
