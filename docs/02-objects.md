# 八项逐一

每项按同一结构写：**测什么 · 算法 · 依据 · 怎么读 · 边界 · 归属**

---

## B1 有没有（覆盖）· 评估

**测什么**：题目提了几个诉求，回答里每个诉求有没有落点。

**算法**
```
① 从 case.md 抽诉求 → 写进 aspects.json
② 人或 LLM 判每个诉求落在哪些语块 → 填 blocks 和 verdict
③ 落空的诉求 → 缺口清单
```

**依据**：ICAT (Findings of ACL 2025) —— 长文本拆成原子断言，与期望的 aspects 算对齐。

**怎么读**：`覆盖 6/6` 不是分数，是「落空数 = 0」。真正有信息量的是**缺口清单**。

**边界**
- aspects 由人抽，抽漏了会误判"没缺口"
- 「有落点」不等于「说透了」——后者是 B2/B4 的事
- 覆盖 100% 不等于没有多余内容（多余内容不在 B1 内计）

## B2 在哪（定位）· 基线

**测什么**：读者最想要的那件事，在第几个位置能找到。

**算法**
```
位置% = 该诉求落点的最小语块起始字符 ÷ 全文清洗后字符 × 100
```

**依据**：PDD (NAACL 2024) 的「位置箱」思路。**但原式是「生成文 vs 参考文」的 KL 散度，需要金标参考答案，评不了单篇**——这里只借用"位置是连贯性的一部分"这个观点。

**位置箱 vs 位置百分比**（容易混）

| | 是什么 |
|---|---|
| 位置百分比 | 「这个人在队伍里排第几」——单点，一个数 |
| 位置箱 | 「把队伍分成 N 段，比较两个队伍各段的人数分布」——分布对比，需要参照物 |

PDD 原文讨论过箱数 N：N = 句子数时等价于 exact match，N = 1 时只看整体分布。**位置百分比相当于 N → ∞ 的极端情况**：只问第一个点在哪，不看后面的分布。

**怎么读**

| 场景 | 好的位置 |
|---|---|
| 只想看结论 | 越前越好 |
| 需要先铺垫风险 | 建议后置合理 |
| 复盘/审计 | 影响详细即可，位置无所谓 |

**只有当你知道读者来干什么，位置才有优劣。** 所以归基线。

**边界**
- 依赖语块识别（见 `01-units.md`）
- 关键词法交叉校验**系统性偏早**——它测的是"词第一次出现在哪"，不是"事第一次被讲在哪"。实测「比较两个方案」关键词给 0.2%，实际比较在第 1 块 10.3%，差 12 个点。

## B3 散不散（集中）· 基线

分两层。

### 微观：句与句（Entity Grid）

**算法**（Barzilay & Lapata 2008）
```
① 每句抽实体（名词 + 英文词，去停用词）
② 标语法角色：S 主语 / O 宾语 / X 其他（位置启发式，见下）
③ 相邻两句比一比
      延续率   = 有共享实体的相邻对 ÷ 总相邻对
      切换率   = 1 − 延续率
      共享强度 = |交集| ÷ min(两边实体数)，分四档
④ 指称距离 = 同一实体相邻两次提及间隔的句数（均值）
```

原文的角色指派用**依存句法分析**。这里没有解析器，用位置近似：
```
第一个名词      → S
动词之后的名词  → O
其余名词        → X
```
**这是工程近似，不是原文方法。**

**依据**：Barzilay & Lapata (2008), Computational Linguistics 34(1)。核心是 Centering Theory——**CONTINUE（两句共享实体）优于 SHIFT（不断切换实体）**。

### 宏观：块与块（主题词分布）

```
跨块数   = 该词出现在几个 L2 语块
跨度     = (末次出现 − 首次出现) ÷ 全文长度
集中度   = 1 − (跨块数−1) ÷ (总块数−1)      1 = 只在一块，0 = 每块都有
```

**怎么读：必须看分布，不能只看均值。**

实测过一个反例：词面重叠（连续值）说 A 更连贯，实体延续率（二元值）说 B 更连贯。拆开分布才看清——

| 共享强度 | A | B |
|---|---|---|
| 完全零共享 | 81% | 70% |
| 轻微 | 1.4% | 8.5% |
| 中度 | 8.7% | 13.4% |
| 高度 | 8.7% | 8.5% |

**两边"高度重合"几乎一样，差别全在轻中度过渡。** A 是两极分化（要么全断、要么强连），B 是均匀型。**均值把两种形状抹成了同一个数。**

**边界**
- 「跨一半以上块的主题词数」是绝对计数，块数不同的两份文本**不可直接比**（一块门槛 4 块、另一份门槛 11 块）
- 纯词面，无共指：「前一份 → PPT」看不见
- 空实体句按"不共享"计入，不剔除（这是口径选择：抽不到实体就是没有实体延续）

## B4 层级（结构形态）· 基线

**测什么**：块怎么切、层级多深、列表粒度多细。

| 指标 | 口径 |
|---|---|
| 标题块数 | L2 语块个数 |
| 块字数中位数 | 各块清洗后正文字符的中位数 |
| Markdown 标题数 | `#`~`######` 开头的行数 |
| **标题层级深度** | 用了几种不同级别的 Markdown 标题；无标题 = 1（平铺） |
| **列表项平均字数** | 最稳的一项，不依赖块识别 |
| 列表项占比 | 列表行 ÷ 非空行 |

**依据**：TSHD (2023) 用标题检测做主题切分。

**怎么读**

- **列表项平均字数最直观**：45 字/条 = 一条里塞两三句话（段落伪装成列表）；19 字/条 = 一条一件事
- **层级深度是类型差异，不是数量差异**：2 层树 vs 1 层平铺，这个比"块数多 3 个"有信息量

**不要报「失衡度（最长块 ÷ 最短块）」**：最短块常常是「需要确定：」这种引导句，这个数测的是引导句有多短，不是结构好坏。

**边界**：无 Markdown 时只能报 1 层——可能真是平铺，也可能格式被压平了，分不清。

## B5 状态 vs 推理 · 评估

**测什么**：读者要的是"现在是什么状态"，回答给的是"不能从哪推出哪"。

**三档**
| 档 | 判据 | 处理 |
|---|---|---|
| ① 完整状态 | 给了具体对象的具体状态（是/否/未知/数量/时间） | 通过 |
| ② 半状态 + 推理 | 关键状态缺失，用"不能推出"代替 | **问题** |
| ③ 纯元话语 | 不回答任何问题，也不给状态和行动 | **问题**（归 B5，不计入 B6） |

**依据**：QUDeval (EMNLP 2023) —— 话语 = 连续提问与回答；把 QUD 的理论约束做成具体协议。

**实例**

| 原句 | 问题 | 改法 |
|---|---|---|
| 「**不能用**前一份的成功**证明**后一份已恢复」 | 后一份到底恢复没有？没说 | 「10月29日那份 PPT **恢复状态无法判定**；只读测试不受影响，可继续。」 |
| 「11月2日已发新包，但**发布不等于**账号、模型、环境已验证可用」 | 到底可用不可用？没说 | 「新包已发；**三者状态未验证**，批量执行前先做最小检查。」 |
| 「以上是建议，**尚未据此**改表、外发」 | 不回答任何问题 | 删掉，或首句写「以下为建议，尚未执行」 |

**为什么这一项比 B6 可靠**

| | B5 | B6 |
|---|---|---|
| 问法 | 这句回答了哪个预设问题？关键状态给了吗？ | 删掉这句会少知道什么？ |
| 候选集合 | ✅ 有（QUD 列表） | ❌ 没有 |
| 混合句 | ✅ 单列 ② 档 | ❌ 二分类装不下 |

**边界**：三档划分是本项目设计的（框架来自 QUDeval，分法无出处）；需第二评者。

## B6 有没有废话 · 观察（不计分）

**测什么**：删掉这句，读者会少知道哪一件具体的事。

**为什么不计分**

1. 三种实现（参考人工 / 本轮人工 / 规则版）逐句一致率只有 **24/45**
2. **构造性矛盾**：排版用的引导句（「建议同时确认：」「需要确定：」）在删句测试下**必然**判无效，但它实际上帮助读者扫读
3. 同一批文本，引导句算不算无效会导致**方向反转**：

| 口径 | A | B |
|---|---|---|
| 引导句算无效 | 3 | 3 |
| 引导句算保留 | 2 | 1 |
| 只数"整句可删" | 2 | 3 |

**四种口径三个方向 → 不满足"换个人看也一样"。**

**后续**：用 10+ 组重跑，若仍无稳定方向则去掉。若保留，按 LREC 2026《Counting on Consensus》的做法**分析分歧模式**（分歧集中在哪类句子），而不是反复换指标。

## B7 指代清不清 · 评估

**测什么**：回指词指向谁，读者能不能唯一确定。

**算法**
```
① 扫回指表达（前/后/这/那一+量词、该+名词、上述、它、其、前者/后者、各层/整组）
② 按类别归类：人 / 文件 / 时间 / 项目 / 层级·分组 / 决策项
③ 逐处判：能否唯一确定？要回看几句？
```

**依据**：Gatti, Martinelli, Navigli (2026), ACL 2026 —— 批评单一总分"不给诊断信息"，主张按语义类别报。

**判据（硬）**
```
能列出 ≥2 个合理对象 → 指代不清
只有一个合理对象     → 清楚
```

**另一档（可扣分）：需读者自己配对**

> 「不能用**前一份**的成功证明**后一份**已恢复」

读者要回到前文数出两个对象（10/27 那份、10/29 那份），靠"前/后"对应才能对上。**这不是"不清"，但读者要额外推理——属于表述问题。**

**必须人工剔误报**：「因此 / 据此 / 此前 / 此外 / 与此同时」里的「此」不是实体回指。代码已用前后向排除，但仍建议过一遍。

**边界**：短回答里指代天然清楚，这一项在长文档上才有区分力。

## B8 数量自述对不对 · 评估（零争议）

**测什么**：说了 N 件，实际列了几件。

**两种检查**
1. 数量声明 vs 实际列举数（「只需拍板三组决定」→ 后面是不是 3 组）
2. 序数回指一致性（「第四层」→ 前面列举够不够 4 层）

**为什么白名单必须有**：实测 15 处"声明"里 11 处不是真声明。

| 不认 | 原因 |
|---|---|
| 「汇总时更费**一点**工夫」 | 程度副词 |
| 「**两个**项目创建失败」 | 具体对象，不是列举 |
| 「**同一组**中」「**第二层**」 | 泛指 / 序数回指 |
| 「只能决定**一件事**，就决定这一项」 | 不是列举声明 |

**列举计数分三种（缺一不可）**
```
a. 同行：冒号后按 、／； 数项
b. 同块内的编号行 1. 2. 3.
c. 同块内的列表行 - •
```

**只在一个 L2 语块内数**，不能跨块——否则会把后面小节的列表也算进来。

**边界**：零争议（数一数就知道），但触发频率低。若 10 组里一次都不触发，降为抽查项——**一个零争议判据如果永远不触发，做进总分也只是个 0。**
