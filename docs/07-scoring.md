# 计分机制

> 四层不是四种权重。它们回答**三个不同的问题**：
> **层4** 一次扣多少 · **层3** 计几次 · **层2** 谁说话算数 · **层1** 要不要合成一个数。
>
> **四个一起调，永远调不清楚。从层4 往上定，每层都能单独验证。**

---

## 一、四层各自管什么

```
层1  维度      措辞 / 信息组织        → 两个独立分数，不合成
层2  对象      11 项里 5 项进分       → 权重 pending
层3  问题项    计什么、计几次          → 去重单位 + 递减 + 饱和   ← 已定
层4  严重程度  每次扣多少              → 三档 + 1:2:4            ← 已定
```

---

## 二、层4：三档 + 几何系数（已定）

### 判据按读者行为定，不按"我觉得严重"

| 档 | 读者会怎样 | 系数 | 单次扣分 |
|---|---|---|---|
| **轻** | 注意到了，但不影响理解 | ×1 | **5** |
| **中** | 要停下、回看、自己补一步推理 | ×2 | **10** |
| **重** | 会得出错误结论，或漏掉一个决策 | ×4 | **20** |

单次扣分 = 基数 5 × 严重度系数。

### 为什么是三档

| 档数 | 问题 |
|---|---|
| 两档 | 分不出"读着别扭"和"读错了" |
| **三档** | 够用 |
| 五档以上 | 没有判据支撑，是假精度——评委自己也说不清 3 档和 4 档的区别 |

### 为什么是 1:2:4，不是 1:2:3

**读者感受是"要不要重读"，不是线性量。** 等差会把"读错结论"和"多读一遍"拉成同一量级。

1:2:4 的意思是：**一个让人读错结论的错，等于四个让人略过的小毛病。**

---

## 三、层3：三个机制（已定）

### ① 去重单位 = 一个可指认的阅读障碍点

**不是命中次数。**

| 反例 | 正确 |
|---|---|
| 「前一份 / 后一份」算 2 处 | **1 处**——它们在同一句里，是一个障碍点 |
| 「必须」出现 8 次算 8 处 | 按概念算 1 处 |
| 同一句话里两个回指算 2 处 | 按句算 1 处 |

代码里已落实：`b7_anaphora.scan()` 的 `需配对数` 按**句序去重**，不按命中数。

### ② 递减：同类问题第 1/2/3 个 ×1.0 / 0.7 / 0.5

**读者的痛感是边际递减的。** 第一句废话很刺眼，第五句就麻木了。

不减的话，一份啰嗦的长回答会被同一个毛病打穿到 0 分，**反而不像读者的真实体验**。

### ③ 不除分母，改用饱和

| 做法 | 问题 |
|---|---|
| 除以句数 / 篇幅 | 长文本占便宜；而且分母怎么定没有依据（句数？字数？段落？） |
| **不除 + 递减 + 饱和到 3 个** | ✅ 长文本不会一路累加 |

**饱和**：同一类问题第 4 个起不计。递减和饱和必须同时有——只有递减，长文本仍会累加；只有饱和，前几个的权重没变化。

## 四、层2：哪些进分（已定）+ 权重（pending）

### 11 项里只有 5 项进分

| 组 | 对象 | 进分 |
|---|---|---|
| **核心** | A2、B1、B5、B7、B8 | ✅ |
| 基线 | A1、A3、B2、B3、B4 | ❌ 只报数 |
| 观察 | B6 | ❌ 只列清单 |

**基线项永远不进分**：句长 28 字 vs 24 字谁更好，**没有定论**。把它塞进总分等于用无依据的数稀释有依据的数。

### 权重：默认等权，状态 pending

```
5 个核心对象等权（各 20%）
```

**为什么不能定**：权重应该由"这一项和人工偏好的关系"决定，而现在只有 1 组 case。**先定权重再算分，就是用未验证的数去验证未验证的数。**

---

## 五、层1：两个维度不相加

### 为什么不能加

措辞 83 分的意思是"有 2 个词读者不认识"；
信息组织 100 分的意思是"没有需要读者多走一步的地方"。

**加起来没有意义。** 它们不是同一量纲。

### 默认输出：两个数 + 一个冲突提示

```
措辞分         100
信息组织分     89.5
冲突           措辞更好（差 10.5 分）
```

**"冲突"本身是最有信息量的输出**——它告诉你这份回答是"词说清楚了但结构乱"，还是"结构清楚但有行话"。

### 如果确实要一个总分：短板加权

```
总分 = 0.6 × 较低维度 + 0.4 × 两个维度的平均
```

**为什么加权均值 + 最低分**：读者体验是**短板主导**的——措辞烂到读不懂，信息组织再好也没用。

**这个 0.6 / 0.4 同样是设计选择，pending。**

## 六、Case1 算一遍

### 问题清单（已按去重单位整理）

| 对象 | A | 严重度 | B | 严重度 |
|---|---|---|---|---|
| A2 | 0 | — | 2 个未解释概念 | 中 |
| B1 | 1 个缺口（Daily） | 中 | 0 | — |
| B5 | 3 句②档 + 1 句③档 | 中 / 轻 | 0 | — |
| B7 | **1 处**需配对 | 轻 | 0 | — |
| B8 | 0 | — | 0 | — |

### 算分

**A**
```
B1   100 − (5×2×1.0)              =  90
B5   100 − (5×2×(1+0.7+0.5)) − 5  =  73
B7   100 − (5×1×1.0)              =  95
B8   100
信息组织 = (90 + 73 + 95 + 100) / 4 = 89.5
A2   = 100
```

**B**
```
A2   100 − (5×2×(1+0.7))          =  83
信息组织 = 100
```

### 结果

| | A | B |
|---|---|---|
| 措辞分 | **100** | 83 |
| 信息组织分 | 89.5 | **100** |
| 短板加权总分 | **91.6** | 86.4 |
| 维度冲突 | 措辞更好（+10.5） | 信息组织更好（−17） |

**判定**：措辞 A 好 17 分；信息组织 B 好 10.5 分；短板加权 **A 好 5.2 分**。

### 但这和人工偏好相反

**人工盲评选了 B。**

三个数告诉我们的：

1. **两个维度的信号几乎完全抵消**——A2 扣 17 分，信息组织扣 15 分
2. **任何"平衡两者"的算法都会给出接近持平的结果**
3. **短板加权的 5.2 分刚好在 5 分阈值边缘**——小数点在决定胜负

> **这不是算法没调好，是数据在说：这一题两个维度打平了。**
> **而人工选了 B，说明人做了加权——他们更在意信息组织。**

## 七、现在能定什么、不能定什么

| 层 | 状态 | 为什么 |
|---|---|---|
| **层4 严重程度** | ✅ **已定** | 三档判据是读者行为，1:2:4 是可解释的换算 |
| **层3 计分单位** | ✅ **已定** | 去重单位、递减、饱和都是机制，不是权重 |
| **层2 对象范围** | ✅ **已定** | 哪 5 项进分有依据（零争议门槛） |
| **层2 权重** | ❌ **pending** | 要等"分项 vs 人工偏好"的关系 |
| **层1 是否合成** | 🟡 **默认不合** | 报两个数 + 冲突提示，比一个总分有信息量 |

### 落地顺序

```
第 1 步  ✅ 修去重单位（B7 2 → 1），把"问题项"定义写死
第 2 步  ✅ 定三档判据 + 1:2:4，冻结
第 3 步  ⏳ 在 10+ 组上跑，只记录「每个对象各扣了多少」，不算总分
第 4 步  ⏳ 看每个对象的扣分方向 vs 人工偏好，一致率 ≥ 7/8 的才有资格进总分
第 5 步  ⏳ 权重由一致率高的对象分配，不是平均分
```

## 八、三个检验（定完权重必须过）

| 检验 | 怎么算 | 不过怎么办 |
|---|---|---|
| **零分检验** | 两份都接近 100 分？ | 这题没区分力，不参与排序 |
| **方向检验** | 总分方向 vs 人工偏好，一致率多少 | < 7/8 → 权重不成立 |
| **翻转检验** | 权重 ±20%，排序变不变 | 变了 → 说明在噪声区，不该定这个权重 |

### 还有一条：差距小于 5 分算持平

单评者的一致率噪声就有这么大。**"87 分 vs 79 分"可以说；"94.0 vs 93.7"不能说 B 赢。**

---

## 九、一句话

> **层4 用三档和 1:2:4（已定）；层3 用"一个可指认的障碍点"做单位 + 递减 + 饱和（已定）；层2 只有 5 项进分、权重等权挂着 pending（不能定）；层1 不合成一个总分，报两个数 + 冲突提示。**
>
> **"体现差距"靠三档几何级差和 5 分持平阈值；"平衡整体"靠递减 + 饱和 + 不除分母。**
>
> **但 Case1 算下来两个维度信号抵消，任何平衡算法都给接近持平——说明"平衡"可能是伪需求：读者实际是有偏好的，人工选了 B 就是证据。**

## 十、`scoring.json` 怎么写

放在 case 目录下，和 `aspects.json` 并列：

```json
{
  "A": {
    "A2_用词熟悉度": [],
    "B1_覆盖": [{"类型": "漏答（Daily Meeting 消失）", "严重度": "中", "个数": 1}],
    "B5_状态vs推理": [
      {"类型": "半状态+推理", "严重度": "中", "个数": 3},
      {"类型": "纯元话语", "严重度": "轻", "个数": 1}
    ],
    "B7_指代": [{"类型": "需读者自己配对", "严重度": "轻", "个数": 1}],
    "B8_数量自述": []
  },
  "B": { ... }
}
```

| 字段 | 含义 |
|---|---|
| `类型` | 一类问题（**同一类型共用一个递减额度**） |
| `严重度` | `轻` / `中` / `重` |
| `个数` | **去重后**的障碍点个数，不是命中次数 |

跑 `python -m plaineval.cli cases/…` 就会输出计分结果。
