# 切分口径

> **改任何指标之前先读这一页。** 所有指标都建立在切分上，切错则全错。

---

## 一、三个层次

```
全文
├─ L1 位置段   开头 / 主体 / 结尾      —— 互斥、覆盖全文、纯位置维度
├─ L2 语块     按标题切出的块           —— 互斥、同级   ← 位置%、块数、集中度用它
└─ L3 分支     语块内部的内容分支       —— 包含关系、可嵌套
```

**不要把三层混在一张表里。** 曾经把「开头/正文/结尾」（位置）和「方案A / 方案B」（内容分支）放进同一个清单，结果看不出谁是包含关系，整张表读不出结构。

**诉求（aspect）不在这棵树里。** 诉求是"用户要什么"，从题目抽；语块是"文本在干什么"，从文本判。两者多对多：

```
诉求「比较」    → 语块「论证」里的分支 A / 分支 B
诉求「拍板」    → 语块「待决策」
语块「执行安排」→ 不对应任何诉求（作者自己加的）
```

## 二、L2 语块怎么切

`plaineval/units.py: sections()`

一行被认作标题，按优先级：

| # | 条件 | 结果 |
|---|---|---|
| 0 | 在表格区内 | ❌ 不是 |
| 1 | 以 `#` 开头 | ✅ 是 |
| 2 | 列表项（`-` `•` `1.`）或噪声行 | ❌ 不是 |
| 3 | 汉字数 = 0 或 **> 16** | ❌ 不是 |
| 4 | 以 `。！？，、；` 结尾 | ❌ 不是 |
| 5 | **下一行是列表项** | ✅ 是（强信号） |
| 6 | 汉字数 **≤ 10 且不含逗号** | ✅ 是（弱信号） |

每个标题到下一个标题之间 = 一个语块。

### 为什么要三条兜底规则

| 真实情况 | 只认 `#` 的后果 |
|---|---|
| 有的回答全文没有 `#`，标题是独立短行（`建议结论`、`推荐执行顺序`） | 算成 1 块 |
| 有的回答全文**没有一个空行** | 靠空行分段会算成 1 段 |
| 表格被压平成文本后每格都是短行 | 一份 20 块里有 7 块是表格行 |

## 三、表格区识别（最容易被忽略的一条）

表格压平成纯文本后长这样：

```
维度                       ← 短标签
方案A：按一级能力分组        ← 短标签
方案B：按风险和副作用分层     ← 短标签
覆盖可见性                  ← 短标签（这是一行的名字）
好，能快速看到每项能力测了多少  ← 长内容
单阶段能力分布不完整，需要通过Sheet汇总 ← 长内容
执行效率                    ← 短标签
相同前置条件可集中准备，批量执行更顺畅  ← 长内容
...
```

**这些短行满足条件 5/6，会被当成标题。**

`table_zone()` 的判据：**连续 ≥4 个"形状一致"的周期**——短标签后跟同样数量的长行（表格一行 = 1 个标签 + N 个内容格，N 固定）。

**列表项会打断周期**，所以「标题 + 列表」的普通小节不会被误判。

### 曾经踩过的两个坑

| 错误规则 | 后果 |
|---|---|
| 「连续短行 + 长行交替 ≥6 行」 | 把「标题 + 列表」的小节也判成表格，块数从 9 掉到 5 |
| 不要求周期形状一致 | 「方案A的影响」后面只跟 1 行长文，被当成表格的一行，块被吞掉 |

## 四、作者句怎么切

`plaineval/units.py: clean_units()`

```
① 按 。！？ 切（**不切分号**）
② 排除 # 标题、URL 来源行、Export to CSV
③ 排除独立短行标题
④ 排除压平表格的单元格
⑤ 排除来源标签（≤6 字、不以句末标点结尾）
⑥ 保留引导句（以「：」结尾且含动词）
```

### 为什么不切分号

分号连接的是同一句里的并列成分。切开会把「句内的强关联」变成「句间的零共享」，直接污染 B3：

示例 case 里两份回答都没用分号连句，所以切不切对它们没有影响。

这一条是在**另一个真实 case** 上发现的：切分号让句数虚高 40%（70 → 51），延续率被压低 16%（0.19 → 0.22）。

### 为什么要排除标题和表格格

实测一份结构化回答的 75 个"句子"里，**28 个是标题和表格单元格（37%）**。

| | 未清洗 | 清洗后 |
|---|---|---|
| 句数 | 27 / 45 | 27 / **37** |
| 句长均值 | 28.19 / 17.96 | 28.19 / **20.38** |
| 延续率 | 0.5385 / 0.4318 | 0.5385 / **0.5833** |

**回答 B 的句长均值从 20.38 被压到 17.96，延续率从 0.58 被压到 0.43**——全是那 8 个独立短行标题造成的。回答 A 用 `#` 标题，本来就被排除了，所以不受影响。

### 为什么要保留引导句

「建议直接拍板：」「需要确定：」这类句子以冒号结尾、含动词，是**作者句**——它们正是 B6（废话）要判的对象。排除掉 B6 就没有输入了。

## 五、位置百分比的口径

```
位置% = 该语块起始处的「清洗后正文字符」÷ 全文「清洗后字符」× 100
```

- **用字符，不用句序号**：读者按字读，不按句读。一个 60 字长句和 5 字短句各算一句，但读者花的时间差 12 倍。
- **分母必须清洗**：去掉 markdown 装饰符和链接 URL。实测一份回答 26.8% 的字符是 `[原消息](<https://example.com/l/message/…>)` 和加粗标记，直接算会把位置% 偏 4.5 个点。
- **定位用语块**：先找到是哪个 L2 语块，再用该块的起始字符算百分比。

---

## 六、跨指标的口径一致性

| 指标组 | 用哪个单位 |
|---|---|
| 句长 / T-unit / B3 微观 / B5 / B6 / B7 / B8 | **作者句（清洗后）** |
| 位置% / B3 宏观 / B4 | **L2 语块** |
| 字符位置 | **清洗后正文** |

**三者必须同源。** 曾经出现同一份文本在三处报出 51 / 58 / 70 三个"句数"，就是因为三个脚本各自切了一遍。
