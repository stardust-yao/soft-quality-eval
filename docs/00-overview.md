# 总览：十一项，分两半

> **这套东西测的是「说人话」，不是文笔。** 一个回答可能用词精准、句子工整，读者还是要读两遍才能拼出答案——那就是不合格。

## 一、十一个对象

### 措辞层（3 项）——「每个词、每个句子本身好不好懂」

| # | 对象 | 读者心里问的 | 归属 |
|---|---|---|---|
| **A1** | 词汇多样性 | 用词是不是翻来覆去就那几个 | **基线（权重 0）** |
| **A2** | 用词熟悉度与解释 | 这个词我不认识，他说了吗 | **评估（唯一计分项）** |
| **A3** | 句法（句长 / T-unit） | 一句话里塞了几件事 | **基线（权重 0）** |

### 信息组织层（8 项）——「散在文中的信息，读者能不能高效拼起来」

| # | 对象 | 读者心里问的 | 归属 |
|---|---|---|---|
| **B1** | 有没有（覆盖） | 我问的几件事都答了吗 | 评估 |
| **B2** | 在哪（定位） | 我要的东西在第几段 | **基线** |
| **B3** | 散不散（集中） | 同一件事要不要翻几处 | **基线** |

| **B7** | 指代清不清 | 「这一项」是哪一项 | 评估 |
| **B8** | 数量自述对不对 | 到底几件事要我拍板 | 评估（零争议） |

## 二、为什么分基线 / 评估 / 观察

判断一个对象归哪边，**看的不是"能不能自动算"，而是"这个数本身有没有好坏"**。

| | 基线 | 评估 | 观察 |
|---|---|---|---|
| 判据 | 看不出优劣，等数据够了划阈值 | 能明确判定为错 | 判定有结构性争议 |
| 例子 | 句长 28 字 vs 24 字，谁更好？没有定论 | 说「三组」实际四组 | 引导句算不算废话 |
| 现在怎么用 | 只报数，不判 | 直接扣分 | 只列清单 |

**这条区分是整套评测的骨架。** 曾经按"能不能自动算"分类，把「数量自述」这种零争议的东西放进基线，把「块数」这种没有优劣的东西差点拿去做判据——都错了。

## 三、评估项的硬门槛：零争议

```
能否进扣分项 = 换一个评委看同一处，是否必然给出相同判定
```

| 对象 | 两个评委会一致吗 | 能否扣分 |
|---|---|---|
| B8 数量自述 | ✅ 数一数就一样 | ✅ 可以 |
| B7 指代（需配对） | ⚠️ 多数一致 | ✅ 可以（需第二评者） |
| A2 用词熟悉度 | ⚠️ 要看证据链 | ✅ 可以（唯一计分项） |
| B1 覆盖 | ⚠️ 要先拆诉求 | 待验证 |
| B5 状态 vs 推理 | ⚠️ 三档划分需验证 | 待验证 |
| **B6 废话** | ❌ **实测三种实现逐句仅 24% 一致** | **暂不能** |

> **不是"我觉得明显错"就能扣分，得是"换个人看也一样"。**

## 四、跑一遍的流程

```
① 准备 case 目录
     case.md  +  a.md  +  b.md  +  aspects.json
                                    ├─ qud            （B5 的预设问题）
                                    ├─ aspects_a/b    （B1/B2 的诉求与落点）
                                    └─ inventory      （A2 的概念清单）

② 一条命令跑全部自动部分
     python -m plaineval.cli cases/case01 --html out/report.html

③ 手工补三样（脚本只给候选）
     · B5 逐句判档：这句回答了哪个 QUD？关键状态给了吗？
     · B6 删句测试（观察用，不计分）
     · B7 逐处判：能否唯一确定所指？需不需要读者自己配对？
     · A2 逐词判：熟悉 / 不熟悉 / 证据不足（按四条硬标准）

④ 判定结果写回 judgments 文件，下一轮复用
```

**第 ③ 步不能自动化。** 把语义判断做成脚本，等于把一个不可复核的判断藏进代码里。

## 五、Case1 的实测结果（11 项）

| 对象 | A | B | 说明 |
|---|---|---|---|
| A1 词次 / 词型 | 854 / 389 | 897 / 397 | 篇幅接近 |
| A1 MSTTR-50 | 0.8835 | 0.8847 | 差 0.0012，测不出差别 |
| **A2 未解释陌生概念** | **0** | **2**（冒烟验证、低依赖Case） | **A 更好** |
| A3 句长均值 | 27.79 | 23.55 | 差 4.2 字 |
| A3 每 T-unit 从句数 | 2.23 | 2.06 | — |
| B1 缺口 | 1（漏 Daily Meeting） | 0 | **B 更好** |
| B2 拍板位置 | 79.3% | 68.0% | **B 更早** |
| B3 延续率 | 0.2391 | **0.5217** | **B 高 118%** |
| B4 列表项平均字数 | 45.5 | 18.9 | 方向未定 |
| B4 标题层级深度 | 2（两层树） | 1（平铺） | 类型差异 |
| B5 候选 → ②档 | 8 → **4 句** | 0 | **A 差** |
| B6 | 观察项 | 观察项 | 四种口径三个方向 |
| B7 需配对 | **2 处** | 0 | **A 差** |
| B8 声明不一致 | 0 | 0 | 零触发 |

**人工盲评偏好 B（回答 B）。**

**两个维度方向相反**：措辞上 A 更好（B 有 2 个未解释黑话），信息组织上 B 更好（4 项占优）。**人工选了 B。**

> **说明在这一题上，读者更在意「信息好不好找、读起来断不断」，而不是「某两个词认不认识」。**
> 但这只是**一个 case 的一个观察**，不能推广。

## 六、五个必须记住的口径

| # | 口径 | 不做的后果 |
|---|---|---|
| 1 | **语块按标题切，但要能认「独立短行标题」和「压平表格」** | 一份 20 块里 7 块是表格行 |
| 2 | **作者句不切分号** | 句数虚高 40%，延续率被压低 |
| 3 | **位置% 分母用清洗后正文** | 长链接和加粗标记会把位置偏 4.5 个点 |
| 4 | **看到分布，不要只看均值** | 连续值指标和二元值指标会给出相反方向 |
| 5 | **基线的数不等于质量** | 句长、块数、集中度都没有绝对好坏 |

细节见 `01-units.md`。
